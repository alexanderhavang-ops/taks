PROJECT INTENT
--------------
TAKS is a control plane for operating TAK Server deployments.

It is being developed and tested in a Swedish Hemvarnet context, but is NOT
Hemvarnet-specific. The goal is to support:

- single TAK Server nodes
- clustered TAK Server deployments
- federated TAK Server hierarchies

Across airgapped, cloud (AWS), or hybrid environments.

A first-class goal is to pair traditional TAK administration with GenAI-assisted
operational views (Tactical Ops, Security Ops, System Health).


SOURCE VS RUNTIME (NON-NEGOTIABLE)
---------------------------------
Source (git):
  /opt/taks
  - public/sanitizable
  - no secrets, certs, hostnames, or battalion names

Runtime (operational):
  /opt/tak/tools/takctl
  - what systemd runs
  - contains venv, deployed code, logs, config
  - drift is possible unless explicitly converged

DEPLOYMENT MODEL (LOCKED IN)
----------------------------
Strategy 1 is chosen:

  tak-installer apply

The installer is the single source of truth for converging:
  - takctl runtime code
  - takctl.conf rendering
  - systemd units (e.g. takctl-web.service)
  - nginx wiring for enrollment + WebUI
  - users/groups and permissions

Manual rsync and ad-hoc changes are transitional only.

## Python package layout (IMPORTANT)

All runtime Python code lives under:

  takctl/takctl/

This is the *only* import root for the `takctl` package.
Do NOT place Python modules under:

  takctl/services/
  takctl/web/
  takctl/api/

Those paths are non-packaged and will not be imported.

Installers may copy files into /opt/tak/tools/takctl/,
but the internal layout must preserve takctl/takctl/.
